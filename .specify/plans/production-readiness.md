# Implementation Plan: BizzBills Production Readiness Hardening

**Branch**: `001-production-readiness` | **Date**: 2026-08-28 | **Spec**: `.specify/specs/production-readiness.md`

**Input**: Feature specification from `/specs/production-readiness.md`

## Summary

Close the verified production-readiness gaps in BizzBills without rewriting working features:
(1) stop error-info leaks on public/portal routes, (2) validate admin user-creation input,
(3) make deployment self-healing (auto migrations in entrypoint) and document `PORTAL_SECRET`,
(4) drive ESLint to clean (85 errors → 0; suppress/raise relevant react-hooks rules), and
(5) add tests for money rounding and recurring-invoice cron. Approach is surgical per the
project's own CLAUDE.md (simplicity-first, surgical changes).

## Phases

### Phase 0 — Research (done inline)
Audit via tsc/lint/vitest/grep + route sampling. Findings captured in spec. No open
clarifications; `requireSuperAdmin()` and HMAC portal token treated as trusted.

### Phase 1 — Design
- Validation helper: email regex, password min-length 8, role enum (SUPER_ADMIN, ADMIN,
  MEMBER, VIEWER), orgId existence check via `prisma.organization.findUnique`.
- Portal: replace `Failed to load portal data: ${message}` with generic
  `Failed to load portal data`.
- Entrypoint: `npx prisma generate && npx prisma db push --skip-generate && node server.js`
  (db push matches the repo's no-migrations convention).
- Lint: the 85 errors are dominated by `react-hooks/set-state-in-effect` and `no-unused-vars`.
  Plan: fix genuine unused vars; for `set-state-in-effect` in camera/OCR effect, wrap in
  guarded call or disable the single rule in `eslint.config.mjs` with a documented reason
  (camera start is a side-effect, not state derivation).
